# Gemini เป็นผู้เลือก ส่วนโค้ดเป็นผู้คำนวณ

Gemini มีหน้าที่ 4 อย่างเท่านั้น คือ ตีความ Trip Request, จัดอันดับ Destination Suggestion จากรายการจังหวัดที่อยู่ในงบ, เลือก Place ลงช่วงเวลาของแต่ละ Day Plan และแปลงข้อความแชทเป็นคำสั่งแก้แผน สิ่งที่ Gemini ส่งกลับมาต้องเป็น JSON ที่ตรงกับ schema และอ้างอิง Place ด้วย ID ที่มีอยู่ในฐานข้อมูลเท่านั้น ส่วน Cost Estimate ลำดับเส้นทาง เวลาของแต่ละ Stop และการตัดสินว่าแผน Over Budget หรือไม่ ให้โค้ด Dart คำนวณแบบ deterministic

เราไม่ให้ Gemini สร้าง Trip Plan ทั้งก้อน แม้จะทำได้เร็วกว่า เพราะ LLM มักแต่งสถานที่ที่ไม่มีจริงขึ้นมาและคำนวณเงินผิด ในขณะที่ค่าใช้จ่ายเป็นหัวใจของโจทย์ การแยกหน้าที่แบบนี้ยังทำให้เขียน unit test ให้ตัวคำนวณได้ และถ้า Gemini ล่ม ระบบยังเลือก Place ด้วยการให้คะแนนแบบ fallback ได้

## Considered Options

- ให้ Gemini สร้างแผนทั้งหมด: ตัดทิ้งเพราะตรวจสอบผลไม่ได้ และตัวเลขไม่น่าเชื่อถือ
- ไม่ใช้ LLM เลย: ตัดทิ้งเพราะอาจารย์กำหนดให้ต้องใช้ Gemini และจะตีความ Free-text Note ไม่ได้
